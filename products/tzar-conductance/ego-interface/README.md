# TZAR Ego Interface · candidate 0.1.0

Локальный цифровой модуль различения голоса эго и сборки **кандидата истинного запроса**. Он не диагностирует личность, не подавляет эго и не выдаёт собственную формулировку за истину субъекта.

Модуль встроен в TZAR Conductance как режим `Эго-интерфейс`. Платформа принимает от изолированного представления только технические статусы `READY / PRESERVED / REVIEW / FAILED / DISPERSED` и его высоту; пользовательский текст через интеграционный канал не передаётся.

- Платформенный маршрут после публикации: `https://lacinnik.github.io/-tensor-architectonics/?mode=ego`
- Прямой маршрут: `https://lacinnik.github.io/-tensor-architectonics/ego-interface/`

## Запуск

Откройте `index.html` двойным щелчком. Интернет, установка и сервер не нужны. Введённые данные не отправляются наружу. Черновик сохраняется в `localStorage` только после явного включения переключателя «Сохранять локальный черновик».

При желании можно запустить локальный сервер:

```bash
python3 -m http.server 4173 --directory /полный/путь/к/tzar-ego-interface
```

и открыть `http://127.0.0.1:4173/`.

## Смысловой контракт

Маршрут интерфейса:

1. **Голос эго** сохраняется как исходная форма, но не признаётся целым.
2. **Точка** различает объект, внутренний образ, позицию и внимание: `O ⊕ I`.
3. **Пять геометрий** проводят форму через режимы `Gᴱ → Gᴸ → Gᴿ → Gᴾ → Gˢ`.
4. **Матрица 4×4** связывает внутренний уровень с внешним доменом.
5. **Алгебра действия** сохраняется в паспорте как `F = (Az × Бука × TX) ⊕ (Объект ⊕ Образ) @ Геометрия | α, IЯ, Cm, Q, T`.
6. **Кандидат истинного запроса** редактируется и явно подтверждается субъектом.
7. **Осевой допуск** требует явных критериев, затем шесть QENGINE создают проверяемый паспорт перехода.
8. **Обратная связь** возвращает наблюдаемый результат в новую Точку.

## Шесть движков

- `QP-01` — Point Engine: не допускает слияния объекта и внутренней конфигурации.
- `QR-01` — Resonance Engine: сопоставляет структуры по явным критериям и пользовательским метрикам.
- `QG-01` — Geometry Transition Engine: исполняет только разрешённый переход с отдельным вердиктом инварианта.
- `QA-01` — Axis Gate: проверяет локальное подтверждение сессии, роль, область и четыре явных критерия.
- `QC-01` — Chronos Engine: ограничивает TTL, защищает от повторного nonce и выполняет логическое освобождение.
- `QI-01` — Invariant & Provenance Engine: проверяет локальную печать, происхождение и критерии до и после перехода.

## Границы утверждений

- Статус модуля: `candidate-local-reflection`.
- «Истинный запрос» — только кандидат до явного подтверждения субъекта.
- Метрики `α`, `IЯ`, `Cm`, `Q`, `T` вводятся пользователем и имеют рекомендательный, а не авторизующий характер.
- Подтверждение сессии локальное; это не внешняя аутентификация.
- SHA-256 перепроверяется в браузере; это не авторская криптографическая подпись.
- Завершение цикла очищает UI и локальный черновик логически, но не обещает физически необратимое удаление данных устройством.

## Проверка

```bash
node tests.mjs
```

Набор проверок охватывает успешный путь и fail-closed сценарии каждого из шести движков.

## Файлы

- `index.html` — семантика и структура интерфейса.
- `styles.css` — адаптивный визуальный слой.
- `app.js` — навигация, локальный черновик, исполнение и экспорт.
- `ego-core.js` — оркестрация полного контура и паспорт результата.

- `manifest.json` — машиночитаемое описание модуля.
- `CONTEXT-MAP.md` — карта собранного контекста и принятых смысловых решений.
