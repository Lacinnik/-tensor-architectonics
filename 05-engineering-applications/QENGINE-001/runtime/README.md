# TZAR-QENGINE reference runtime

Статус: `reference-candidate` · версия `0.1.0-rc.2`. Формат результата остаётся `tzar.qengine-result/0.1.0-rc.1`; исправления усиливают проверки входов, не меняя структуру результата.

Эталонный кандидат реализует единый контракт `QEngine(Request, Context, Policy) → EngineResult` для `QP-01`, `QR-01`, `QG-01`, `QA-01`, `QC-01` и `QI-01`.

Публичный стенд: https://lacinnik.github.io/-tensor-architectonics/qengine/

Исполнимый модуль расположен в [`products/tzar-conductance/qengine/qengine.mjs`](../../../products/tzar-conductance/qengine/qengine.mjs), чтобы один и тот же файл использовался тестами и публичным браузерным стендом.

Запуск проверок:

```bash
node 05-engineering-applications/QENGINE-001/runtime/tests.mjs
node --test 05-engineering-applications/QENGINE-001/runtime/fail-closed.test.mjs
```

Ожидаемый результат: `TZAR-QENGINE reference candidate: 35 assertions passed.`

Дополнительно: девять тестовых сценариев отказа. Проверяются отсутствие обязательной подписи, нулевой/неверный бюджет переходов, некорректное время, TTL и допустимое отклонение часов, несогласованные типы нагрузки/ёмкости и не-объектные JSON-входы всех шести движков. Правильные исходные примеры и отказ повторного nonce сохранены. Публикация Pages теперь запускает обе проверки до загрузки артефакта.

Локальная приёмка 2026-09-20: 35 исходных утверждений и девять новых тестов проходят. В браузерном стенде QI-01 без подписи, но с `requireSignature: true` и доверенными входными флагами, возвращает `DENIED / SIGNATURE_INVALID`, `invariantVerdict: review`, `output: null`. Проверка экспорта и полная браузерная матрица всех шести движков в этом проходе не выполнялись.

Проверки не доказывают истинность переданных флагов внешних механизмов: поле `verified: true` само по себе не выполняет криптографическую проверку. Нельзя использовать публичный стенд как сервер авторизации. Межпроцессное хранилище nonce, восстановление после перезапуска и независимые проверки происхождения остаются вне этого runtime.

Границы: runtime не выполняет криптографию, аутентификацию, авторизацию операционной системы или физическое уничтожение данных. Он принимает явные результаты внешних проверяемых механизмов и закрывает операцию при отсутствии обязательного свидетельства.
